Life Guard Technical Reference Manual Section 1: Working Principles

01. Working of Life Guard

Life Guard is an end-to-end mission-critical personal protection and community emergency response platform. Unlike conventional panic-button applications that simply send a generic text or fail when cellular signals falter, Life Guard is engineered around active dead-man threat detection, continuous geospatial corridor tracking, and a redundant dual-channel emergency dispatch pipeline.

1.1. High-Level Working Philosophy

The system operates under the fundamental premise that a victim in imminent danger cannot unlock their phone, navigate an interface, or compose a text message. Life Guard eliminates friction through four synchronized operating modes:

Mode 1 Guard Mode (Dead-Man's Touch)

The user places their thumb on the pulsating center shield when walking through unsafe, dimly lit, or unfamiliar environments. While held, the app is armed. If the victim is attacked, incapacitated, or their phone is snatched, the release of touch triggers a silent 30-second PIN challenge. If the secret 6-digit PIN is not entered, the emergency pipeline immediately fires.

Mode 2 Double-Tap Instant SOS

For sudden, overt emergencies (e.g. physical assault, vehicle collision, medical trauma), double-tapping the central shield within 300ms instantly bypasses the countdown and immediately broadcasts full-scale SOS alerts to primary contacts and nearby community responders simultaneously.

Mode 3 Route Deviation Guard

When commuting via cab, auto, or night transit, the user imports their Google Maps route. Life Guard calculates perpendicular Cross-Track Distance ($d_{\text{xt}}$) every 5 seconds. If the vehicle veers more than 100 meters off the planned corridor, a 30s PIN challenge begins, alerting family if kidnapped or diverted.

Mode 4 Inactivity & Safety Check-In Timer

Users traveling alone or exercising set a countdown timer (5 to 60 mins). Scheduled via exact hardware alarms, the device sounds a check-in alert. If unanswered or unverified with the secret PIN within the window, the system assumes incapacitation and executes automated emergency escalation.

1.2. Dual-Channel Emergency Alert Pipeline

When an emergency is validated, Life Guard executes a parallel, two-pronged broadcast:

  • Channel A: Direct Cellular & Telephony (100% Offline Resilient) — Using Android's native SmsManager, the device transmits emergency SMS messages containing exact latitude/longitude and a live Google Maps tracking URL to the designated emergency contact (e.g. family member, brother 20km away). This requires zero internet connection and operates over bare GSM cellular signal.
  • Channel B: Communal Cloud Proximity Mesh (FCM Push Broadcast) — Simultaneously, the device posts coordinates to the FastAPI cloud backend. The server queries all registered community users, computes geospatial distance using the Haversine formula, and dispatches high-priority Firebase Cloud Messaging (FCM) push alerts. Nearby responders' phones wake up, sound a piercing siren alarm, and display a "Navigate to Victim" button with turn-by-turn routing.

1.3. Proactive Indoor Location & Self-Healing Resilience

In Version 9.1, two groundbreaking architectural improvements guarantee reliability in real-world conditions:

🛰️ Proactive Location Acquisition (Zero "0,0" GPS Locks)
On app launch and prior to dispatching any SOS payload, the client triggers Google Play Services getCurrentLocation(PRIORITY_BALANCED_POWER_ACCURACY). This leverages WiFi BSSID scanning and cellular triangulation to acquire an indoor position in <1.2 seconds, ensuring that testing inside a house never sends an invalid coordinate.
🔄 Dynamic Proximity Expansion (5km to 25km Safety Fallback)
If zero community helpers are detected within the immediate 5,000m radius, the cloud server automatically widens the spatial query up to 25,000 meters (25 km). This ensures that suburban neighbors, town volunteers, or family members stationed across the city are mobilized rather than dropping the alert.

Hosting Render Cloud Web Services

Fully automated continuous deployment (CI/CD) hooked to GitHub main branch. Provides SSL/TLS termination, automated health checks, and global edge routing at https://life-guard.onrender.com.

Database TiDB Cloud Serverless / SQLite

Multi-dialect hybrid persistence: utilizes distributed TiDB Cloud MySQL with native GIS spatial functions (ST_Distance_Sphere) and seamlessly falls back to embedded SQLite with Python Haversine math during outages.

Push Routing Google Firebase Admin SDK

Direct integration with Google FCM HTTP v1 API using compressed base64-encoded Service Account credentials, dispatching instant notifications with custom notification channels and data payloads.

7.2. Security, Cryptography & Privacy Safeguards

Security Salted SHA-256 PIN Vault

Every secret PIN is combined with a static cryptographic salt (lifeguard_pin_salt_2026) and hashed via SHA-256. Plaintext PINs are never stored in SharedPreferences, SQLite, or cloud database tables.

Resilience Self-Healing Failover Engine

If the cloud MySQL database (TiDB or Aiven) times out or terminates, the backend instantly engages an embedded SQLite database with zero downtime, auto-recreating user profiles so active devices are never dropped.
